## 5. 重点 skill 说明

### 5.1 金融用语混淆识别

这是当前最容易被误读的一个 skill。

它**不只是**处理：

- 理财
- 投资
- 存款
- 保本
- 本金/利息/复利

它还会覆盖一部分：

- 社保/医保不足对比
- 社保/医保贬低
- 保险与银行/基金/理财的片面对比
- 保险利益与金融收益的边界混淆

所以像 `KB0013 知识库规则-社保 / 医保` 出现在 `金融用语混淆识别` 里，是**当前设计下的正常行为**，不是 prompt 串错。

### 5.2 简单对比/绝对化识别

这个 skill 当前覆盖两类主问题：

- 极限词、绝对化：`第一`、`最好`、`唯一`、`最优`
- 简单对比/贬低：`比银行更高`、`比社保全面`、`比同业更好`

从静态映射看，它已经覆盖：

- `6.2.1` 贬低同业或同业产品
- `6.3.1` 片面对比金融产品
- `7.1.x` 极限词/断言式承诺
- `7.2.1` / `7.3.1` / `7.5.1`

这说明你现在最关心的“绝对化夸大表述”已经有独立 skill 兜底，不再只是落在基础 `SKILL_LANGUAGE`。

## 6. 当前结构的几个观察

### 6.1 `financial_confusion` 是最大桶

静态映射数量达到 `177` 条，明显比其他复杂 skill 大很多。  
这意味着当前“金融混淆”仍然是一个**过宽的复杂簇**，内部其实包含多个子问题：

- 保险 = 理财/存款/基金
- 保本/本金/计息
- 社保医保不足对比
- 个人养老金与理财产品关联

如果后续要继续做效果优化，这一簇最值得再细分。

### 6.2 基础 `SKILL_CONSUMER` 和复杂 `financial_confusion` 有明显重叠

基础层里 `消费者保护检测` 已经承接大量 `financial_confusion` / `responsibility_exaggeration`。  
复杂层又有 `金融用语混淆识别`。

这说明项目当前是：

- 基础 skill 负责**基础归类**
- 复杂 skill 负责**真正复杂精判**

这种设计是合理的，但从命名上容易让人以为“基础 skill 和复杂 skill 是完全分开的主题簇”，实际上并不是。

### 6.3 仍有一些规则落在 `通用合规检测`

当前还有 `32` 条规则仍然主要依赖 `DEFAULT_SKILL`。  
这通常意味着：

- 规则的 `primary_category` / `category_group` 不够完整
- 或者还没有单独抽出稳定的 skill 簇

这批规则后续很适合继续做知识治理。

## 7. 建议怎么使用这张表

如果你的目标是继续优化 skill 体系，我建议按这个顺序看：

1. 先看**复杂 skill 大桶**
   - `金融用语混淆识别`
   - `简单对比/绝对化识别`
   - `收益承诺/稳定收益暗示识别`
2. 再看**仍然偏薄的复杂 skill**
   - `税法/法律误导识别`
   - `传承/资产转移类误导识别`
   - `跨段落逻辑判断`
3. 最后看**兜底 skill**
   - `通用合规检测` 中还剩哪些规则没有被明确结构化

## 8. 一句话结论

当前 skill 体系已经不是“几个大而化之的 prompt”，而是一个：

- 基础 skill 做基础分簇
- 复杂 skill 做复杂精判
- `financial_confusion` / `comparison_or_absolute` / `guaranteed_return` 为重点能力中心

的双层 skill 体系。

但其中最值得继续治理的，依然是：

- `金融用语混淆识别` 桶过大
- `通用合规检测` 仍有兜底残留
- 少数复杂 skill 规则量偏薄
